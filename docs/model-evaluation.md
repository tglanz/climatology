# Model evaluation

The model estimates finite-run time-mean zonal-mean target profiles from short
input windows. Targets and their physical units come from the saved configuration.

Run from the repository root:

```bash
uv run --project ml --all-groups ml evaluate model --training-dir <training-dir>
```

Use `--device cpu --n-workers 0` for serial CPU execution.
The [sample contract](pre-processing.md) defines simulation acceptance, inputs,
targets, and coordinates. The [norms reference](norms.md) defines scores.

## Saved contract and inputs

Evaluation loads configuration, numerical weights, normalization, and split
assignments from the training directory. It verifies the saved prepared artifact
manifest and reads those exact windows, targets, and simulation identities. It
does not reopen raw trajectories. Checkpoint and sample metadata must agree,
including actual coordinates and every target channel. See the
[pipeline overview](pipeline.md) for artifact schemas and commands.

Each simulation prediction averages its window predictions. Physical-unit scores
then average simulations equally. Prepared-window evaluation instead scores
individual saved windows. These aggregation levels answer different questions.

The pipeline rejects artifacts without a completed prepared manifest or a saved
run reference. Existing artifacts remain untouched. Prepare and train into fresh
directories to adopt the new path. Evaluation can use a relocated, byte-identical
prepared artifact with `--prepared-dir PATH`.

## Reports

The command writes `evaluation/report.md`, `evaluation/scores.json`, physical
profile arrays in `evaluation/profiles.npz`, input hashes in
`evaluation/inputs.json`, and figures.
The report uses only figures generated by that invocation. Old image files do not
authorize their inclusion.

Each target has its own numerical tables and physical-unit plot labels:

| Result | Meaning |
|---|---|
| Baselines | Zero, training mean, nearest configuration, parameter ridge, short-window wind mean, and model |
| Replicate variability | Mean relative deviation from the finite replica mean, with replica counts |
| Generalization | Mean simulation errors by configuration and forcing parameter, colored by split |
| Error structure | Simulation errors, bias profiles, and relative-error distributions |
| Zonal-wind extrema | Latitude and magnitude of the strongest absolute profile value |

Unavailable training baselines remain unavailable. Missing parameter metadata
cannot silently turn a nearest-configuration baseline into a training mean.
Zero-reference relative errors are excluded and counted; RMSE remains available.
Split coverage distinguishes assigned, loaded, and excluded simulations and gives
exclusion reasons.

Training curves show the configured loss on normalized targets and filter metrics
to the saved run when its identifier is available. Their values need not equal
physical-unit evaluation errors.

Replicate deviation is descriptive variability. It is neither a standard deviation
nor a demonstrated lower bound on model error. A point below an equality diagonal
does not establish an accuracy limit.

Worst-configuration figures plot mean profiles. Their titles show mean simulation
errors; those values need not equal the error between the plotted mean profiles.
Peak diagnostics apply only to zonal wind and do not identify a specifically
eastward jet.

Notebook source calls these shared APIs. Historical saved notebook outputs are
retained and do not establish that the corrected calculations have regenerated
those earlier experiments.

## Evidence for learning and generalization

Use whole forcing configurations as split groups. Windows from the same
trajectory and replicas of one configuration must stay together. Random window
splits can test recognition of a trajectory rather than transfer to new forcing.
This follows the grouped-validation principle in [Roberts et al. (2017)](https://doi.org/10.1111/ecog.02881).
Keep test configurations fixed across heads and seeds. Use validation only to
choose a checkpoint or hyperparameters. Report interpolation and extrapolation
as separate experiments; a single test split does not establish both.

The report adds these checks:

- **Constant output:** compare physical MSE with the training-simulation mean.
  Skill is `1 - model_MSE / reference_MSE`; positive values favor the model.
- **Parameter lookup:** compare with nearest training configuration and a fixed
  linear ridge map from standardized forcing parameters to configuration-mean
  targets. Fit coefficients and scaling on training configurations only.
- **Simple averaging:** compare with target-field means over the exact saved
  input windows. This reference may have extra measurements: the wind average
  observes wind even when the network receives only vorticity. It tests whether
  the learned prediction improves on direct short-trajectory averaging.
- **Output collapse:** report the ratio of predicted to true configuration
  variance, their centered anomaly correlation, and regression slope. A constant
  profile has zero variance; high correlation with a small slope still indicates
  underestimated response amplitude. Use the anomaly scatter to locate failures.
- **Input identity:** compare correctly paired configuration predictions with
  199 shuffled pairings within the same split, seed 17. Report the fraction of
  shuffled MSEs at least as good as the observed MSE, with a plus-one correction.
  This is a conditional association check. Correlated forcing and initial states
  prevent a causal interpretation. It requires at least three configurations.
- **Uncertainty:** bootstrap paired MSE improvements over 1000 configuration
  resamples. Keep replicas together. Intervals are descriptive and unstable with
  few configurations; do not treat latitude points or windows as independent.
- **Representation:** show Gaussian-weighted Legendre energy and the error from
  projecting true targets onto truncated bases before learning. The basis is
  orthonormal for weights summing to one; see [NIST DLMF](https://dlmf.nist.gov/18.3).
- **Temporal information:** save prediction dispersion across windows and the
  fraction of input snapshots inside the target averaging interval. Overlap
  permits reconstruction claims but weakens claims of future prediction.

`evaluation/scores.json` retains these results under each target's `learning`
field. `profiles.npz` includes split labels for paired comparisons across heads.
New prepared files include `window_baselines (N,C,H)`. Older prepared files remain
loadable, but their short-window reference is explicitly unavailable.

A convincing result improves on the mean and parameter baselines on held-out
configurations, resolves their different profiles, and performs better with
correct input/target pairing. Beating short-window averaging supports value beyond
an instantaneous estimate. Several training seeds and finite-run replica targets
are needed before ranking heads confidently. Success does not by itself establish
that the network learned the dynamical equations.

## Measured comparison: 2026-11-21

A capped experiment added 39 T85 trajectories (37.9 GB) to 63 existing trajectories.
All 102 passed full spinup, convergence, and climatology checks; each contains
150 segments and 1050 daily snapshots. Whole configurations were split into 75
training trajectories, nine validation cases at forcing latitude 40, and two
nine-configuration tests: latitude 30 interpolation and latitude 70 extrapolation.
The new sample is concentrated at latitude 10. All three heads used identical
prepared data and normalization, one small SFNO trunk, and seeds 17, 29, 43.

The target is the final 500-day mean wind. Evaluation averages five 10-day window
predictions; inputs and targets share no snapshots. The checks are retrospective,
and eight target intervals start before the convergence detector endpoint.
Interpret scores as finite-run profile estimation, not proof of equilibrium or
prospective forecast skill.

| Head | Parameters | Interpolation RMSE (m/s) | Extrapolation RMSE (m/s) |
|---|---:|---:|---:|
| Field | 3889 | 1.223 | 0.984 |
| Profile | 3889 | 1.103 | 0.937 |
| Legendre, 16 modes | 5792 | 1.775 | 1.018 |
| Direct wind-window mean | - | 1.406 | 1.329 |

Model entries average the physical RMSE of three individual seeded runs. These
are not ensemble errors. The profile head beat the field head for every paired
seed and both regimes. Configuration-bootstrap intervals favor it over the field
head for these fixed seeds. The 16-mode target projection error is only about
0.05 m/s, so the Legendre fit's larger error is not explained by truncation alone.

Predictions vary with held-out configurations and outperform the global mean and
simple parameter references. The profile head's single-window RMSE is 1.384/1.111 m/s
(interpolation/extrapolation), versus 2.609/2.243 for direct wind averaging. This
supports learned statistical denoising beyond final-window averaging. With five
windows, average MSE gains over wind averaging are 37.7%/49.8%, but paired
configuration-bootstrap intervals include zero. The wind reference observes wind;
the network receives vorticity. Do not infer learned dynamics or a universal head
ranking from these results.

Qualitative profiles reveal large near-pole errors that Gaussian area weighting
can hide. One profile-head case predicts 7.93 m/s near 89 deg against 0.71 m/s truth,
despite locating the main jet correctly. Test configurations have one realization
each; three seeds and nine configurations per regime leave substantial uncertainty.
Numerical failures were removed and refilled, conditioning the sample on survival.

The detailed report, figures, comparison scripts, configurations, validation
records, hashes, and per-window predictions are retained locally under
`output/heads-20261121/` (ignored experiment artifacts). Start with `report.md`.
The shared workflow remains `preprocess`, `train`, then `evaluate`.
