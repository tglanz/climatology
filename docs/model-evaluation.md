# Model evaluation

The model estimates finite-run time-mean zonal-mean target profiles from short
input windows. Targets and their physical units come from the saved configuration.

Run from the repository root:

```bash
uv run --project ml --all-groups ml evaluate model --training-dir <training-dir>
```

Use `--device cpu --n-workers 0` for serial CPU execution.
The [sample contract](pre-processing.md) defines simulation acceptance, inputs,
targets, and coordinates. The [norms reference](norms.md) defines scores.

## Saved contract and inputs

Evaluation loads configuration, numerical weights, normalization, and split
assignments from the training directory. It verifies the saved prepared artifact
manifest and reads those exact windows, targets, and simulation identities. It
does not reopen raw trajectories. Checkpoint and sample metadata must agree,
including actual coordinates and every target channel. See the
[pipeline overview](pipeline.md) for artifact schemas and commands.

Each simulation prediction averages its window predictions. Physical-unit scores
then average simulations equally. Prepared-window evaluation instead scores
individual saved windows. These aggregation levels answer different questions.

The pipeline rejects artifacts without a completed prepared manifest or a saved
run reference. Existing artifacts remain untouched. Prepare and train into fresh
directories to adopt the new path. Evaluation can use a relocated, byte-identical
prepared artifact with `--prepared-dir PATH`.

## Reports

The command writes `evaluation/report.md`, `evaluation/scores.json`, physical
profile arrays in `evaluation/profiles.npz`, input hashes in
`evaluation/inputs.json`, and figures.
The report uses only figures generated by that invocation. Old image files do not
authorize their inclusion.

Each target has its own numerical tables and physical-unit plot labels:

| Result | Meaning |
|---|---|
| Baselines | Zero, training simulation mean, nearest training configuration, and model on test simulations |
| Replicate variability | Mean relative deviation from the finite replica mean, with replica counts |
| Generalization | Mean simulation errors by configuration and forcing parameter, colored by split |
| Error structure | Simulation errors, bias profiles, and relative-error distributions |
| Zonal-wind extrema | Latitude and magnitude of the strongest absolute profile value |

Unavailable training baselines remain unavailable. Missing parameter metadata
cannot silently turn a nearest-configuration baseline into a training mean.
Zero-reference relative errors are excluded and counted; RMSE remains available.
Split coverage distinguishes assigned, loaded, and excluded simulations and gives
exclusion reasons.

Training curves show the configured loss on normalized targets and filter metrics
to the saved run when its identifier is available. Their values need not equal
physical-unit evaluation errors.

Replicate deviation is descriptive variability. It is neither a standard deviation
nor a demonstrated lower bound on model error. A point below an equality diagonal
does not establish an accuracy limit.

Worst-configuration figures plot mean profiles. Their titles show mean simulation
errors; those values need not equal the error between the plotted mean profiles.
Peak diagnostics apply only to zonal wind and do not identify a specifically
eastward jet.

Notebook source calls these shared APIs. Historical saved notebook outputs are
retained and do not establish that the corrected calculations have regenerated
those earlier experiments.
